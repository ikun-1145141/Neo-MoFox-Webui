# ZIP / MFP 本地插件包导入

## 使用方式

在 **插件管理 → 导入插件包** 中选择一个 ZIP 或 MFP 文件，点击「上传并预览」。检查名称、版本、旧版本、兼容性提示和阻止原因后确认导入。

- 仅支持标准插件包：清单在根目录，或所有文件位于同一个一级目录。清单必须包含主程序要求的 name、version、description、author、dependencies、entry_point，入口必须存在。
- 上传文件和累计解压内容均不得超过 **50 MiB**；不支持加密包、符号链接、特殊文件、不安全路径、多份清单或任意深层源码仓库 ZIP。
- 预览只读取清单和压缩包，不执行插件代码。预览有效期 **15 分钟**，取消或过期自动清理。
- 插件代码拥有宿主进程的权限。结构检查不是安全审计，不应导入不可信来源的包。
- 同名插件需要明确勾选覆盖确认；相同版本和降级会警告，但可确认继续。目录版插件、多份同名插件及插件目录外路径必须手工处理。
- 新插件以清单名称保存为 .mfp；覆盖 ZIP/MFP 插件时保留原来的包路径，确保主程序重载路径正确。
- 配置及用户数据不由导入器删除或重置。插件自己的加载钩子仍可能产生副作用，导入器不承诺回滚代码执行的外部影响。

## 生效与故障处理

普通插件写入后自动尝试加载；已加载的插件执行重载。界面分别显示「已导入并加载」「已写入但加载失败」和「WebUI 更新待重启」。加载失败保留新包并展示可获取的错误，用户应检查日志、依赖和配置；重启不保证修复问题。

导入 **当前 WebUI 自身** 时只写入包，不执行热重载，也不自动重启 Neo-MoFox。请自行重启。已有目录版 WebUI 不支持自动覆盖，第一次安装此功能包需要手工替换原部署，确保插件目录内只有一份 WebUI。

断线后点击「继续查询任务」，不要再次上传。提交响应丢失时，「重试确认同一上传」使用原上传 ID，不重复安装。当前浏览器标签页的 sessionStorage 只保存待确认请求或任务 ID，用于刷新后恢复，不存储插件内容或凭证。任务结果在服务端内存中保存最多 24 小时，重启后丢失；若任务查询返回不存在，先检查插件列表和日志，再清除本地提示。

本操作不会下载其他插件或自动安装 Python 依赖。确定的宿主/API 版本冲突、缺失插件依赖、循环依赖、组件依赖缺失以及会破坏现有插件版本依赖的更新会被阻止；已安装但未加载的插件依赖会警告。

## 接口与实现边界

实际路由前缀为 **/webui/api/plugin**，不同于旧设计文档中的 /api/plugin。全部导入接口使用 VerifiedDep 和 BaseResponse；上传还在 multipart 解析前验证认证并限制请求总字节数（50 MiB + 64 KiB 表单开销）。

| 方法 | 路径 | 请求 / 响应 |
|---|---|---|
| POST | /import/prepare | multipart 字段 file；返回 PluginImportPreview |
| POST | /import/commit | upload_id、confirm_overwrite；返回 PluginImportOperation |
| GET | /import/operations/{operation_id} | 返回任务状态快照 |
| DELETE | /import/uploads/{upload_id} | 清理尚未提交的上传，返回 deleted |

状态为 queued / running / succeeded / failed。**succeeded 表示导入文件成功，不代表插件已加载**；调用方还必须检查 result.written、result.loaded、result.restart_required 和 result.load_error。

上传暂存目录沿用代码中的 WebUI 数据根目录：data/json_storage/WebUI_data/plugin_imports（旧文档简写为 data/WebUI_data）。正式目标使用宿主配置 bot.plugins_dir。请求不能指定服务器文件路径。最多保留 8 个待处理上传和 256 个任务结果；未提交上传每 30 秒清理一次，服务重启时清理本功能随机命名的暂存文件。

导入、市场安装、WebUI 发起的加载/重载/卸载共享进程内写入互斥。提交前重新检查目标路径、大小、mtime、文件身份及 SHA-256，预览后有变化则拒绝。该锁不控制外部进程或手工文件操作，也不支持多个 Neo-MoFox 进程同时写同一个插件目录。

宿主暂无公开的单清单规划 API，因此兼容性适配集中复用独立 PluginLoader 实例的校验方法，不调用全量加载，也不修改主程序。宿主升级时应关注这些适配点。

## 构建本地 MFP

在仓库根目录执行：

~~~sh
cd frontend
npm run build
cd ..
python scripts/build_local_mfp.py --output ../neo-mofox-webui-local-import.mfp
~~~

打包脚本将 Plugin 源码与本次 frontend/dist 的构建产物合并（后者放在包内 static/），排除缓存及旧 static，不需要安装 MPDT，不发布到插件市场，也不改变清单版本。旁边生成 SHA-256 文件。构建产物不会加入 Git。

## 验证状态与手工检查清单

**本次按用户要求不运行自动化测试、不启动宿主、不试装插件。** 仅做源码静态复核、Python 语法解析、前端类型检查和生产构建；这些不能证明运行时功能正确。

待手工确认：

- 标准 ZIP/MFP 根级及一级目录包的上传、预览、确认、加载与列表搜索保持。
- 同名 ZIP 更新保留原路径；同版本/降级确认；目录版及重复来源被拒绝。
- WebUI 自更新写入后保持服务，手动重启生效。
- 损坏包、危险路径、缺清单/入口、过大文件、未认证请求与依赖冲突被拒绝。
- 取消/过期清理，断线恢复，重复确认只生成一次任务。
- 预览后文件变化、写入失败保持旧包、加载失败保留新包并显示失败原因。
- 插件市场安装、原有加载/重载/卸载、窄屏及中英文界面无回归。

后续若另行授权测试，既有回归入口为 python -m unittest discover -s tests -v 及 node --test frontend/tests/model-test.test.mjs；它们不覆盖本次新增导入功能，不能用其通过替代导入专项验证。
